# QA de uso y limpieza de interfaz — 22 de octubre de 2026

Revisión de la aplicación de planos ASSUR CHILE, con datos sintéticos. Alcance: escritorio, disposición de ventana estrecha, dibujo y edición, cierre de paneles, guardado y conservación de datos, exportación e integración de biblioteca. No se alteraron planos privados ni credenciales.

## Cambios aplicados

| Prioridad | Hallazgo verificado | Corrección |
|---|---|---|
| P1 | Un aviso permanente sobre cámaras vacías tapaba el dibujo aunque se trabajara con cercos. | Aviso eliminado. La ayuda inicial solo aparece en un proyecto completamente vacío, se puede cerrar y recuperar. |
| P1 | Varios paneles laterales podían acumularse y reducir excesivamente el área de dibujo. | Cajetín, capas y propiedades se excluyen entre sí. Cierre visible, acceso desde barra superior y panel superpuesto en ventanas estrechas. |
| P1 | Capas calculaba metros con una escala fija, diferente de la calibración del proyecto. | Se suman los segmentos reales y se usa la calibración vigente. Sin calibración se muestran unidades. También se corrigió la referencia de la retícula. |
| P2 | Zoom, deshacer, rehacer, norte y capas se repetían en una barra flotante que tapaba el plano. | Zoom y ajuste se trasladaron bajo el lienzo; se retiraron los duplicados. Barra ocultable y recuperable. |
| P1 | Cerrar el cajetín durante la edición podía descartar notas aún no confirmadas. | El panel permanece montado mientras está oculto: al reabrirlo se conserva la edición pendiente. |
| P2 | Las ayudas y coordenadas ocupaban espacio durante tareas que no las necesitaban. | Coordenadas opcionales y modo Solo plano con retorno explícito a edición. Este modo evita editar o borrar por clic/teclado sobre el lienzo. |
| P2 | Menús quedaban abiertos mientras se interactuaba con otros controles. | Cierre con Escape, clic exterior y botón visible. Menú de opciones con altura máxima y desplazamiento interno. |
| P2 | Atajos del plano podían actuar al escribir en formularios. | Se excluyen campos editables; S/L no interceptan combinaciones con Ctrl/Cmd. |
| P2 | Era posible finalizar geometrías con pocos puntos. | Se requieren tres puntos para polígonos y dos para cercos/rutas. El botón Finalizar comunica el estado deshabilitado. |
| P2 | Cambiar de herramienta podía conservar vértices pendientes de otra operación. | El cambio cancela el trazado pendiente y la medición anterior. Cancelar sigue estando disponible. |
| P2 | El movimiento del puntero recalculaba el cajetín aunque no se estuviera dibujando. | El puntero en selección sin coordenadas ya no actualiza ese estado; el ajuste de notas se reutiliza mientras no cambien texto, espacio o fuente. |

## Comprobaciones

- 35 pruebas automáticas correctas: validación de archivos, persistencia de notas y formatos, PDF con continuación, simbología, cercos, etiquetas, colocación libre, ajuste fino, geometría/calibración y biblioteca privada simulada (errores, conflictos y caducidad incluidos).
- Compilación de producción y comprobación de tipos: correctas.
- Chrome en escritorio: aviso retirado, apertura/cierre de cajetín y capas, exclusión mutua, ocultar/recuperar controles, ocultar/recuperar herramientas y modo Solo plano verificados en pantalla.
- Inserción de una cámara y un cerco sobre muro de dos puntos. Finalizar estuvo deshabilitado con un solo punto. Edición de grosor a 3 y etiqueta «Tramo de prueba QA» verificadas.
- Guardado desde Mis planos con biblioteca de prueba: archivo conservó una cámara, cuatro cercos, soporte, grosor, etiqueta y calibración 0,2. Las operaciones de integración están cubiertas además por pruebas automáticas con API simulada.
- Ventana de 390 × 760 dentro de un iframe de Chrome: sin desbordamiento horizontal; lienzo disponible de aproximadamente 390 × 449. Esto verifica disposición, no gestos táctiles.

## Límites de la revisión

- Se utilizó una biblioteca local simulada: no se realizó una nueva escritura en el repositorio privado ni una prueba con otra cuenta/equipo real.
- El navegador de automatización se detuvo al intentar aceptar la confirmación nativa de reapertura. La conservación y apertura de documentos están cubiertas por las pruebas de integración; no se declara completada esa confirmación manual hasta poder verificarla.
- La edición está orientada a ratón y teclado. La compatibilidad con gestos táctiles físicos, Safari/Firefox y el rendimiento con proyectos excepcionalmente grandes quedan pendientes de pruebas específicas.

No se presenta un porcentaje de mejora de velocidad: no se ejecutó un ensayo comparativo cronometrado. Las mejoras de eficiencia demostradas son la eliminación de obstrucciones y controles duplicados, la recuperación de paneles y la reducción de trabajo de renderizado identificable en el código.
